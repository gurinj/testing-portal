## 1. Scope

All catalogue checks of stages 3, 4, 5, 6, 7, 9 and 10 that can run without CMIplus or bank systems. Stage 8 (country packs) stays empty. Checks whose catalogue text depends on CMIplus behaviour ("if CMIplus requires", "where supported", guideline values) are built with a setting and a default, listed in section 4, so they can be adjusted after the test with the bank's files without changing a rule.

Also in M2:
- the settings file and its plumbing (section 3);
- the derived payment type per transaction (section 2), shown in the report;
- reference data: ISO 3166 countries, ISO 4217 currencies with decimals, IBAN registry, SEPA and EEA countries, ISO 20022 external code lists, TARGET closing days;
- a local test mode for the bank's files (section 6);
- a test that breaks and one that passes every new rule, for `.03` and `.09`.

Not in M2: stage 8 content, 5.9 (BIC directory, licensed), 9.9 (needs the app's history), fixes, email, comparison (M3).

## 2. Payment type (stage 3)

Every transaction gets one type, from `js/validation/functions/payment-type.js`, used by the rules of stages 3, 5, 7 and 10 and shown in the report. Inputs: service level codes (block and transaction), local instrument, category purpose, instruction priority, currency (InstdAmt/@Ccy, or EqvtAmt/CcyOfTrf), creditor country (from the creditor IBAN, else the creditor agent BIC, else the creditor address), debtor agent BIC, the selected country and its settings.

| Type (id) | Label | When (first that applies) |
|---|---|---|
| `SEPA_INST` | SEPA Instant | Local instrument in `paymentTypes.instantLocalInstrument` (INST). |
| `SEPA` | SEPA credit transfer | A service level code SEPA on the block or the transaction. |
| `BUDGET` | Budget or tax payment | Category purpose in `paymentTypes.budgetCategoryPurpose`, or creditor IBAN matches the country's `budgetIbanPattern`; creditor in the selected country or unknown. |
| `INTRA_BANK` | Intra-bank transfer | Creditor in the selected country and creditor agent BIC (first 8) equal to the debtor agent BIC or in the country's `bankBics`. |
| `SEPA` | SEPA credit transfer | Currency EUR, selected country and creditor country both in the SEPA scheme list, and not urgent (no service level in `paymentTypes.urgentServiceLevel`, priority not HIGH). Added 2026-11-18 while building: an urgent EUR payment is a domestic urgent or cross-border payment, not SEPA (to confirm with the bank's files). |
| `DOMESTIC_URGENT` | Domestic urgent | Creditor in the selected country (or unknown and currency = local currency), and a service level in `paymentTypes.urgentServiceLevel` or instruction priority HIGH. |
| `DOMESTIC` | Domestic standard | Same, otherwise. |
| `CROSS_BORDER` | Cross-border (SWIFT) | Creditor country known and not the selected country. |
| (none) | Not determined | Creditor country unknown and currency not the local currency (finding 3.5). |

## 3. Settings

`config/settings.json` holds everything that is likely to change. A country file `config/countries/<CC>.json` may contain `"settings": { … }` with the same structure; it is merged over the general settings (objects merged, values and lists replaced). The merged settings of the selected country are passed to the rules worker with each validation and read by the rules through `js:tpSetting('path.to.value')` (functions in `js/validation/functions/settings.js`).

`checks` changes a check without touching its rule:

```json
"checks": {
  "4.2-age": { "severity": "W" },
  "6.12":    { "enabled": false },
  "3.2":     { "severity": "W", "code": "NARR" }
}
```

Keys are check ids, or check id plus part (`4.2-age`) where one check has several asserts. Applied in `findings/report.js` to all findings of stages 2–10; stages 0 and 1 stop the run and cannot be switched off.

Durations are ISO 8601 (`P1M` one calendar month, `P30D`, `PT1H`), amounts are strings (`"999999999.99"`), `null` means "no limit / not set" and switches the check off.

## 5. Conventions for the rule files

- Written for `.03`, compiled for `.03` and `.09`; where the structures differ, cover both (BIC vs BICFI: `(p:BIC | p:BICFI)`).
- Assert ids `R<id>` or `R<id>-<part>`; role = catalogue severity; flag = reason code.
- `[1]` for single elements; `castable as` before conversions; leave values the XSD rejects to the XSD; keys for duplicates; no positional predicates in key `match`; simple contexts (see `docs/RULES.md`).
- Settings through `js:tpSetting(...)`, reference lists through `js:tpIn('list', value)`, payment type through `js:tpPaymentType(tx)`.
- Messages say what is wrong with the actual value, in plain English.

## 6. The bank's files (local test mode)

`tests/files/bank/` (ignored by git and left out of the zip) takes the bank's files. `node tests/run-bank.js --record` validates them for a given country (`AT_file.xml` → AT) and writes the findings per file as rule id → count to `tests/expected/bank/<file>.json`; `node tests/run-bank.js` (and every build) compares with what was recorded. The expected files contain no values from the payment files, so they can be shared.

## 8. Decisions while building (to confirm with the bank's files)

Recorded as the stages were merged; each is easy to change (rule file or settings).

- Stage 4 (h1, merged 2026-11-18):
  - An address of only `Ctry` and `AdrLine` is unstructured (EPC style); only other elements make it structured. 4.30 checks structured and hybrid addresses; 7.8/7.18 warn about unstructured ones.
  - 4.13/4.14 (PmtTpInf / ChrgBr on block and transaction) are reported on each transaction.
  - 4.18-account added (ChrgsAcctAgt without ChrgsAcct, ISO ChargesAccountRule).
  - 4.17 rejects a debtor agent given only as `Othr/Id` NOTPROVIDED.
  - 4.37: with `guideline.localInstrumentProprietary` `[]` every proprietary local instrument is an error.
  - 4.39 checks only SCOR references that start with RF and two digits.
  - Duplicates avoided: the charges account IBAN is 4.18-iban (not 5.6), the regulatory reporting country is 4.40-country (not 5.10), a missing creditor agent of a cross-border payment is 4.26 (7.17 checks only a present agent).
  - Known overlaps to review with real files: two `Ustrd` in a SEPA payment give 4.38-count, 6.3 and 7.6; 4.30-lines and 6.3 `PstlAdr/AdrLine` both limit address lines.
- Stages 5 and 6 (h2, merged 2026-11-18):
  - 5.1/5.2 leave typed values (dates, amounts, IBAN, BIC, codes with an XSD pattern) to the XSD; 5.3 and 5.4 still check them. Header values use the country's set; block values the set of the block's payment type (cross-border: SWIFT X; mixed: the country's set); transaction values the set of their type.
  - 5.4-blank skips MsgId, PmtInfId, EndToEndId and Cdtr/Nm (4.1, 4.6, 4.20, 4.28 report them).
  - 6.6 checks only what the country file lists under `currencies` (by payment type id); without a list the currency is left to stage 7 (7.1 SEPA EUR, 7.10 Instant EUR, 7.13 domestic local currency), so one problem is reported once.
  - Default settings changed so a problem is reported once: `guideline.maxOccurs` no longer has `RmtInf/Ustrd` (4.38 with `remittance.maxUstrd`), `guideline.maxLength` no longer has `RmtInf/Ustrd` (XSD), and `checks."4.30-lines"` is off (6.3 limits `PstlAdr/AdrLine` for every address).
  - 6.11 compares agents by the first 8 characters of the BIC (a branch is the same bank).
  - 6.10 `initiatingPartyIdPattern` is a JavaScript regular expression (anchor it with `^…$`).
- Stages 9 and 10 (h4, merged 2026-11-18):
  - 9.2–9.5 find duplicates with one JavaScript index per file (`functions/stage9.js`) instead of XSLT keys: four keys cost 1.0–1.6 s per 10,000 transactions, the index 0.1–0.3 s.
  - 9.5 (possible duplicate): same creditor account, amount (as a number), currency, execution date and remittance text, across blocks.
  - 9.6 does not fire when both account currencies are given and differ (sub-accounts of one IBAN).
  - 10.1 does not check blocks with only SEPA Instant payments (24/7) or dates in the past (4.10). TARGET applies to EUR payments that are not SEPA Instant.
  - 10.2 `cutOff`: one time (`"14:00"`) or per payment type with `default`; compared with the time of the computer running the check.
  - 10.6-ultimate and 10.10 give one hint per block, not two.
  - 10.8 (information) on every .03 file where the country also accepts .09; `hints.version03` switches it off.
  - 10.9 has no `size` part: the CMIplus file size limit is not known (the tool's own limit is 20 MB).
- Stages 3 and 7 (h3, merged 2026-11-18):
  - 3.6: a `paymentTypes` list in the country file decides (`[]` = none offered); without it SEPA types need `sepa: true`.
  - 3.7: transactions without a payment type (3.5) do not make a block mixed.
  - 7.4 is an error for SEPA by service level (or SEPA Instant) and a warning (`7.4-implicit`) for a EUR payment between SEPA countries without service level, which the bank may send another way (to confirm).
  - 7.6 leaves names to 6.4 when `guideline.maxLength` limits them to 70 or less, and the number of remittance parts to 4.38 when `guideline.remittance` allows one Ustrd or one Strd (the defaults), so each problem is reported once; with other settings 7.6 reports them.
  - 7.8 (SEPA) and 7.18 (cross-border) warn about fully unstructured addresses only when `guideline.unstructuredAddress` is true; same definition as 4.30.
  - 7.14 cannot fire: a creditor IBAN of another country makes the payment cross-border (kept as a guard).
  - 7.17 checks only a creditor agent that is present (a missing one is 4.26).
